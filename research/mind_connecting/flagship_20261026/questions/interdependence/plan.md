# Conditional plan: how connection history makes a partner matter

## Scientific quantity

The principal quantity is how much **formation with repeatedly interleaved work changes the later cost of replacing a familiar partner**, on common fresh tasks. For an episode family, let `D_h = loss(swap,h) - loss(placebo,h)` for formation history `h`. Compare `D_interleaved - D_batched`. Report actual success and raw coordination/time costs separately, not solely a ratio whose denominator changes. No test of consciousness, number of subjects, or an irreducible essence of the pair is involved.

## Concrete smallest setting

Use a four-operation dependency chain over small symbolic records: resolve a lookup, apply a rule, resolve another lookup, then choose an actual output. Public input tables and functions are identical for both systems; final records change on every problem. Both must first demonstrate every individual operation; that prerequisite has not been established here. Assign two operation slots to each side during formation. `AABB` and `ABAB` have the same chain, operation multiset and balanced workload, but one versus three cross-boundary edges. Include role-reversed counterparts and rotate operation types/positions to avoid making A systematically the planner. This is a precisely specified partition of a graph, not a claim that all psychological complexity is a matched scalar.

The first implementable diagnostic uses **text packets and explicit persistent notebooks**. Its opportunity is reduced request/wait overhead relative to a less adapted pair executing the same imposed partition. The serial chain provides no inherent parallel speedup; a same-budget serial solver is only a competence/resource reference. Whether the four-step scale supports a measurable useful history effect is unestablished. Avoid extending it merely until the desired effect appears.

### Proposed text task and state contract

Both agents receive all public tables/functions and the initial record. At each synchronous tick, each can emit one structured action, capped at 64 generated tokens. Draft horizon: 16 ticks, so at most 1,024 action-generation tokens per agent, with unused capacity reported. Actions are `EXEC(node,value)`, `SEND(node,value)`, `REQUEST(node)`, or `WAIT`. EXEC enters a model-generated value into that agent's private ledger; only the assigned owner can also commit that node to the task ledger. EXEC for a downstream node requires the preceding node to be present in its private ledger, through its own execution or receipt. Nonowners may execute and recompute earlier nodes, consuming their own action slots, but cannot commit another owner's node. This is a restriction on credited operations, not a claim to count the model's hidden computations.

SEND can copy only a value actually present in the sender's ledger. The exact packet is delivered to the other ledger before the next tick; REQUEST is likewise delivered next tick. No automatic answer follows a request. The engine exposes committed-node status but not another agent's value, chooses no requests, and computes no intermediate for an agent. Incorrect generated values remain in ledgers; truth-based scoring/feedback arrives only after the episode. Node labels, valid action syntax, and current ownership are public and canonical. These rules make communication and recomputation alternative legal routes while ownership remains imposed.

Record success, committed-node correctness, completion tick, counts of EXEC/SEND/REQUEST/WAIT, and generated tokens for **all** episodes. An incomplete episode retains its incomplete flag and observed 16-tick resource use; do not silently turn that into a correct-completion latency or average only successful cases. This isolates operational overhead; identical tick/token allowances do not establish equal hardware latency or identical inferential work.

After each formation episode, each agent writes a fixed-schema notebook of at most 192 tokens, under the same retention rule in both arms. It may record experienced partner handoff behavior and prospective coordination advice, but no task facts or verbatim historical ownership instructions. At the next episode, reset the entire task transcript, K/V cache and private task ledger; retain only this notebook, which is re-prefilled alongside the current task. Notebook truncation is mechanical at the fixed limit; record realized lengths and rejected fields. The current ownership block explicitly governs this episode; no old system/task prompt is retained. A stale-ownership statement that leaks into a notebook remains a possible failure mode and must be separately coded, not interpreted as anticipation. The swap moves the incoming agent's notebook, role and fixed prompt; placebo reinstatement uses the same reset. Fresh evaluation facts cannot be carried in the notebook.

After formation, all histories receive the same prespecified mixture of fresh evaluation graphs and the same current ownership instructions. Pair swaps occur only between equally formed, role-matched teams within a history arm. Preserve each incoming agent's complete allowed state. A placebo uses identical notification, context reset and timing while restoring its original member. Evaluate the immediate first episode and a fixed recovery horizon separately; ongoing adaptation must not be hidden in one average. Fresh task facts are fully provided in every test branch. No formation answer can solve a held-out input.

This main contrast answers the effect of historical topology. It does not match acquired communication volume, learned conventions or effective practice by post-treatment regression; these may be how topology has its effect. Equalize exogenous examples, available work allowance and assigned operation exposure prospectively. If actual successful practice differs, report that alternative path and restrict the claimed mechanism accordingly.

## Distinguish what acquired dependence consists of

1. **Primary total-effect contrast:** randomized formation partition × placebo/experienced swap, evaluated on common tasks. No fresh-replacement comparison is required to identify this interaction, although it can characterize general experience.
2. **Anticipation intervention, only after observing an action-level candidate:** clone each pair's own pre-handoff state; states across formation histories are not claimed identical. For example, if discovery traces suggest that interleaved-history recipients normally wait for an unsolicited node-2 result at tick 5, move that already-generated exact text packet from delivery at tick 5 to tick 7, retaining the 16-tick horizon and 64-token-per-tick allowance. Compare unchanged delivery, delayed delivery, and a branch restoring delivery at tick 5. No branch receives an ungenerated correct answer. The prespecified confirmation prediction is selective loss of a useful tick-5-to-6 work opportunity or redundant request in the anticipating history, with a smaller delay effect in a nonanticipating history on the **same current task**, and recovery when the expected handoff is restored. Apply these branches to placebo and swapped pairs, plus a same-size delay on an identified noncritical packet. If every recipient merely fails because any indispensable packet arrives after a deadline, this is generic channel dependence and fails the anticipation claim. Discovery chooses the candidate schedule only; a fresh split must confirm its history-specific disruption/rescue. This is a controlled component experiment, not quantified mediation.
3. **Portability/rescue:** supply a finite public handoff contract to both original and swapped pairs, keeping current facts intact, and compare costs/success. A compact contract that removes the swap penalty with preserved utility supports ordinary portable conventions. Residual losses do not prove an ineffable relationship: the contract may omit the important convention. Test a targeted remedy tied to observed failures before making that interpretation.

Canonical packet fields can be fixed from the beginning to reduce arbitrary lexical-code explanations; timing, anticipation and workload conventions remain possible and are not treated as nuisance. A full contract intervention is a mechanistic/systems intervention, not a requirement that the total effect survive controlling away its mediator.

The text diagnostic can establish a task and a notebook-supported causal mechanism. It cannot substitute for the internal-bridge claim. A native extension requires a separately reviewed persistent-state/reset and packet-timing contract plus useful intermediate transfer and return. Moving an unchanged whole native packet in time is conceivable, but semantic agreement of decoded content does not establish equality of native arrays, and no such implementation is validated here. Comparisons across channels require reported capability/cost profiles; matching one mean access score does not match all information. A native-only result without the historical causal contrast is not the proposed contribution.

## What could substantiate a substantial paper

The strongest package would show that randomized formation topology changes later partner specificity on fresh content, locate the effect in acquired anticipatory handoffs through selective action interventions, and show when a simple public contract does versus does not preserve its efficiency. This connects a cause of organization to its portability and repair under imposed work ownership. A validated native extension could then explain how internal coupling supports those handoffs; the text result alone does not. It would not discover cooperation, conventions or transactive memory for the first time.

A useful opposing result is substantial formation benefit with tightly bounded swap cost, even after interleaved histories. That would constrain the hypothesis that repeated cross-boundary computation inevitably makes competence relationship-specific. It has value only with demonstrated history use, adequate precision and a successful task, not from failure to communicate.

## Falsifiers, rivals and stop rules

| Observation | Consequence |
|---|---|
| Native channel cannot reliably support useful intermediate use and return | Stop at feasibility; no negative conclusion about organization. |
| No formation benefit or no measurable dependence on prior history | No evidence of acquired organization at this horizon; do not enlarge horizon post hoc to rescue it. |
| Swap loss tracks inferior isolated operation performance or missing current facts | Component-skill/information account remains; proposed organization explanation is not established. |
| Only current crossing count changes costs; formation interaction is negligible with useful precision | Reject the historical-topology proposition in this setting. |
| Simple explicit schedule restores all utility and cost differences | Ordinary portable convention account is adequate. This can strengthen the causal formation-and-repair contribution; drop only claims of irreducible dependence on a particular partner. |
| Scheduling intervention causes generic failure in every cohort and placebo | It has not located the acquired partner-specific mechanism. |
| Well-informed replacement rapidly adopts the schedule with unchanged cost | Dependence is repairable/portable; no particular-partner necessity. |
| A close original already randomizes formation topology and establishes the same mechanism | Recast as a specified replication or stop novelty investment. |

## Units, selection and missing support

Independent evidence must come from freshly generated formation-and-evaluation episode families. A/B sides, test problems, rounds and cloned interventions are repeated measurements. If two families exchange agents, they form a dependent swap block; uncertainty resamples or randomizes whole independent swap blocks, not individual actions. Predefine the primary history-by-swap contrast and report the raw component contrasts. Mechanistic follow-ups need a fresh confirmation split if selected from observed failures. Invalid answers stay invalid/missing under a stated failure policy; do not silently score missing as zero or retain only successful episodes.

No N, threshold or effect-based selector is adopted here. The next authorized work is a symbolic graph/ownership audit and original-source resolution, then a separately approved competence pilot. Parameter/task selection must obey the existing ACC/CAP/format rules or obtain an explicit new PI decision; the desired partner-specific outcome cannot select prompts or bridge settings. Fresh confirmation cannot reuse exposed V1–V6 episodes. Present data support none of the required joint coverage, native behavior or mechanism estimates.
