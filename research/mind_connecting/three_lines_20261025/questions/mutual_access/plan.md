# Conditional next step, not an adopted experiment

The quantity of interest is the change in unnecessary or omitted acknowledgement decisions when receipt visibility changes, and whether that change differs between native and text content delivery. The intended population is fresh generated short coordination episodes for frozen Qwen3-4B-Instruct-2507; existing V1–V6 records do not answer it.

First resolve the value/precedent gate in `development.md`. If a narrow replication or extension is worthwhile, translate the checked finite worlds into ordinary task observations. A visible receipt must be an actual event with known delivery semantics. No prompt may reveal a hidden success flag. Explicit transport knowledge is allowed, but its effects concern evidence use rather than privileged self-access.

Start with a deterministic counterpart solely to test the task contract, then require useful behavior by both model instances before interpreting pair coordination. The deterministic counterpart is not itself evidence of two-agent mutual understanding. Do not require long reciprocal interaction merely for appearance. A sender acknowledgement, counterpart launch/wait and realized task payoff suffice if each action is actually executed.

Use paired episode branches for delivery route × receipt visibility, with successful factual delivery in the target comparison and separately interspersed genuine delivery failures to make the uncertainty contract credible. Include destination reversals, role reversals and new wording. Record local event histories, actual delivery, acknowledgements, launch/wait, task outcome, invalid outputs and processing identities. Diagnostic factual and perspective questions use separate branches and never certify the cause of an action.

Report the finite condition vector first: factual-use competence, omitted acknowledgements, redundant acknowledgements, counterpart launches/waits and realized utility. The primary contrast, if adopted, is an episode-weighted difference in the visibility effect on acknowledgement error between routes. Each episode receives equal weight; sides, branches and turns are repeated observations. Pair bootstrap intervals would resample episode families. Joint claims across endpoints need a prespecified combination or multiplicity rule; a descriptive vector does not justify a selected significance claim.

Do not select only successful native action branches and call that factual matching: such selection is post-treatment and changes the population. Independently calibrated transfer and prespecified task eligibility may support a bounded comparison, but equal diagnostic accuracy cannot certify equal usable information. If relevant factual competence remains unequal, report the route contrast as confounded by access and stop the stronger interpretation. Parameter selection must follow existing ACC/CAP/format limits; no outcome-guided tuning on the acknowledgement endpoint. Any pilot, calibration and confirmation sets must be separate, with any new research choices approved by the PI before adoption.

A native-specific unsupported-certainty pattern, matched on the relevant checks, could motivate explicit receipt support. Similar errors across routes favor generic perspective-management difficulty. Accurate behavior would constrain this proposed failure mode within the tested task. Acknowledgement rescue alone shows the value of information, not a special representation. Poor basic transfer, unstable counterpart policy, uncertain receipt semantics, or insufficient precision are inconclusive rather than negative evidence. No mechanism claim follows without further discriminating intervention.

Unresolved necessities: original-source novelty/replication value; the usable native channel; jointly adequate first-order competence; legitimacy of the observation contract; a task-relevant tolerance and sample-size target. This document provides no numerical sample size because none is justified by the purely logical check. It does not recommend GPU expenditure yet.
