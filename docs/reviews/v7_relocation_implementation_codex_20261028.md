## What changed

`src/mb/v7_relocation.py` implements the new comparison without changing the engine. The saved 12 `v7_dev` episodes, all 24 actual P-token sequences and span lists, original notes, and old BF16 diagnostic files are pinned by SHA256. The current materials/notes must reconstruct the saved inputs exactly before a model is loaded. There is no new note generation for the comparison.

For each batch candidate (1/4/8/12 episodes), one native prefill is cloned into two independent branches. The production branch uses `ONE`, KV-P, w2, all layers, `before_own`, with span logging. The reference invokes a real model prefill: A has its native position IDs and each B has valid positions `[−L_B, 0)`, calculated from that row's unpadded length. Only B's actual prefilled K/V and initial state are copied into the reference clone. A's cache and all initial tensor fields are checked bitwise identical to the original snapshot. B's next position is zero. The logical span declarations stay identical; reference prefill offsets and the zero read-time offset are recorded separately, so the native arm's logical bank metadata is not mistaken for physical rotary coordinates. The reference never calls `rephase_keys`.

Both branches consume the same neutral `Continue` token for eight teacher-forced ticks through `Engine.step`, `make_plan` and the production joint attention. Compare all A rows, all layers, all query heads and every declared own/donor span. Full-vocabulary logits use atol 0.003 / rtol 0.002; masses use atol 0.002 / rtol zero, as approved. Comparisons test each element before summarizing; a single head/span failure cannot disappear under averaging. There are 384 episode/tick/batch comparisons, with exact coverage checked. Only error summaries, provenance, logical declarations and timings are persisted, not full attention matrices or decoded continuation text.

FP32 equivalence is the gate. The same comparisons in BF16, plus native joint-read batch/padding variability against batch 1, are diagnostic only. Their numerical differences never decide admission. Nonfinite comparisons are represented explicitly and remain JSON-safe. The former cache-level BF16 envelope is retained verbatim as historical evidence, not recomputed or widened.

`src/mb/v7_acceptance.py` now requires `--saved-input-dir` and the revised approval hash. It stops on a failed FP32 gate, then runs descriptive BF16, the existing R1 sweep, and the 336 CAP0 runner checks. The runner exercise uses the fixed largest candidate batch (12 episodes / 24 rows) so batch selection can occur only after it passes. The measured fastest translated/logged candidate is then written into the pilot config. No pilot is launched by this module. Exceptions preserve a failed receipt and cannot produce an admitted pilot config.
