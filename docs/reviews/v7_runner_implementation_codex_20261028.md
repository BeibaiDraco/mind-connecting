# V7 runner implementation for Claude review

Author: Codex, 2026-10-28. Scope: engine-review R3/R4 integration, after the independent draft/material review in `v7_protocol_materials_review_codex_20261028.md` (commit `ad64c92`). No protocol, material generator, analysis script, model or experiment was changed/run.

## Entry point and scope

`src/mb/v7_run.py` provides the separate V7 collector. The only legacy-runner edits are two overridable methods for episode construction and mention counting; their default behavior is unchanged. The V7 adapter reuses the existing reflection/readout dispatch, branch isolation, tick serialization and two-pass retry loop. It registers exactly the current draft's 14 base arms and four arms for each table/laptop variant. Base collection has 261 trials per episode (18 forced-choice answers per arm, plus nine open reports); each other variant has 40. Only A is measured.

The four-arm generalization table still lacks ORIG counterfactual, as identified in the protocol review. The collector does not add an unapproved cell or compute a pooled P2 from mismatched cells. An adopted arm-table change must update the registry and coverage tests before freezing.

Configuration fields are `split`, `variant`, `n_episodes`, `tag`, `seed`, `episodes_per_batch`, `max_rows`. Splits are `v7_dev`, `v7_pilot`, `v7_formal`; variants are `base`, `table`, `laptop`. The initial pilot is restricted to 80 base episodes. No formal N is supplied by default. A revised pilot's fresh episode namespace needs an explicit protocol amendment; changing the seed alone does not create new episode IDs.

`python -m mb.v7_run CONFIG.yaml` only prints the schedule. `--execute` additionally requires `--approved-protocol-sha256` matching the PI-approved draft. This is an operator attestation, not proof that approval has occurred. Dev execution is restricted to 12–24 episodes. Formal execution also checks the protocol, config and package sources against the `protocol-v7` tag. No approval receipt, frozen config or tag was fabricated here. `prepare_run` is an offline preparation API; callers of the collector directly are responsible for the same launch approval. There is no automatic gate, analysis, sample-size calculation or next-stage dispatch. Completeness always reports `consumable: false`; scientific admission belongs to the separately reviewed analysis workflow.

## Material wiring and provenance

- Private prefix: the V7 card, actual generated note, chat closure and reflection prompt. Strict-third-person B uses the legacy third-person reflection prompt and forced note opener. A remains second person. The opener is not generated or appended twice.
- The full-information C0 arm moves the fact to A. Counterfactual arms change only B's neutral fact, with fixed assignment labels and question/option meanings. A's original notes are shared across the original/counterfactual pair because its effective counterfactual flag is false.
- Notes are keyed by episode, variant, effective source role, fact holder, effective counterfactual flag, frame and private-prefix token hash. Notes differing in any actual input cannot collide. The log stores context, token IDs and their SHA256; conflicting caches fail closed. Crash tails are preserved byte-for-byte and, on the next append, explicitly identified by a hash marker; malformed interior rows without that marker are rejected.
- Same-content donors take A's complete P tokens and spans, including A's cached note. They do not generate a B note. The metadata records source A for both banks, equal actual card/prefix hashes and no neutral fact; USE's expected meaning is null in this control. Questions retain the original assignment-based meanings.
- Every trial carries `v7_tasks.record_metadata` under `record["v7"]`, extended with `arm_id`, `copy_A`, `partner_frame`, `input_sources`, `note_keys` and `banks`. The actual card hashes replace the helper's second-person defaults for strict-third-person/copy arms. `banks[A/B]` contains logical length, complete-prefix token hash and each declared span's boundaries/token hash/hash. Before-note failures have null banks, not fabricated inputs. Top-level `arm_id` and `variant` support analysis indexing; full arm names are `V7/<variant>/<arm_id>`.
- `first_token`, `system_turn` and all card spans come from the materials. Added spans are `note` (forced opener plus generated continuation), `closure` (end token and newline), and `prompt` (the complete reflection user turn and assistant header). These are unpadded half-open coordinates; empty notes are valid. Private inputs, prefix parts and bank summaries are cached only for the current arm/chunk.
- Linked arms enable span diagnostics. Existing engine fields `kv_condition_identity`, `resolved_condition_hash`, `r_kv_condition_identity`, and C/R/generated-continuation NPZ summaries are retained. C0 has bank provenance but no joint-KV attention summaries. Unlinked RO reflection has no attention measurements; its later readout does. Nothing stores full attention matrices.

## Identity and persistence

Run identity binds the exact schedule, registered arms, all scheduled material/question tokens and spans, model/tokenizer manifests, protocol/material source hashes and package source hash. Identities are JSON-normalized before comparison. Changing material tokens cannot be bypassed by `--allow-code-change`; that option only permits and logs a package-source change on resume. Formal CLI launch remains subject to the frozen-source check.

Resume validates identity, trial membership, condition hashes, note integrity and snapshot consistency before writing its resume event. Immutable run files and old record shards are retained. Completed trials are skipped; failed trials receive one automatic retry per invocation and remain missing if they fail again. No zeros are substituted. Snapshot reconstruction must match its saved fingerprint. Successful prefix preparation and later failed readouts retain their actual input/geometry metadata.

## Verification and remaining acceptance

The new offline tests run the production orchestration through all three variants using a deterministic NumPy engine double. They cover the exact arm/question matrix, paired variants/disjoint split IDs, unique condition/note identities, B-only counterfactuals, full-information routing, exact copied-A banks, third-person hashes/prompts, empty notes, logical span boundaries, RO write flags, NPZ geometry/summary serialization, partial/completed resume, immutable old shards, explicit code-change handling, changed-material refusal, corrupted records/notes/snapshots, note/readout failures and retry exhaustion. These are software fixtures, not model observations or GPU acceptance evidence.

Run the full offline suite with `.venv/bin/pytest -m 'not gpu'`. Final counts are recorded in STATUS with the implementation commit. Claude should review this adapter and its tests before execution. Engine R1 remains a smoke timing measurement (the reviewed attention hot path was not changed). R2 remains a prospective BF16 comparison against the old path's own batch-composition variability on identical saved inputs; no fixed fp32 tolerance is reused as a BF16 margin. GPU acceptance and smoke remain unrun and await PI draft approval.
